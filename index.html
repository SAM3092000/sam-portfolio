HoneywellMRP Audit dashboard

I led the design and development of this material requirements planning (MRP) dashboard from scratch, including its SQL audit rules, .NET 9 API, and React interface. Planners can filter SAP data-quality findings by plant or product, inspect the rule behind each finding, review trends, and export a worklist to Excel.

When a part’s controller assignment fails a check

  1. Check the assignment. Does the part’s controller code map to an active employee in a qualifying planning role at that plant?
  2. Prioritize the finding. If the assignment fails the check, the dashboard flags it for manual review. The planner can use the next 12 months of demand to decide how urgently to investigate.
  3. Verify the correction. The planner checks the source records, corrects the assignment or mapping there, or confirms an exception with its owner. A later audit run shows whether the finding cleared.
How is the audit score calculated?

Each rule has its own set of eligible part and plant combinations. In the illustration, 180 of 1,000 pairs have an open controller finding. That leaves 820 clear, for a score of 82%. The overall score averages the rules with at least one eligible pair.

Other rules check planning settings. For example, one flags a stocked part missing its cycle-count indicator. Another flags a goods-receipt processing time set above five days.

SQL Server · .NET 9 · React · SAP · Excel exports
HoneywellRecognitions app prototype

I led the Recognitions prototype from scratch, defining the workflow, directing the design, and building it in React with GitHub Copilot. Some colleagues couldn’t open the existing Microsoft Form and sent monthly nominations by email. I adapted the form’s branching rules and used the MRP Audit dashboard as the visual reference for the prototype.

From nomination to local history

  1. Choose who to recognize. The first two steps cover recognition size and recipients. Switching from two people to a team clears the individual names and asks for the team name.
  2. Describe the contribution. An earlier nomination credited a planner who coordinated several teams during a material shortage to meet priority demand. The prototype prompts for the contribution, its impact, the behaviors involved, and the recognition month.
  3. Save and find it again. The form validates each step and keeps applicable answers when the user goes back. A saved nomination appears in that browser’s searchable history and can be reopened and printed.
Why count nominations separately from participation?

A two-person nomination creates one saved record. An official participation total needs additional rules about how to count people, teams, and nominations carried into another month. The prototype reports saved-record volume and leaves the official participation total pending.

The four-screen prototype passed six automated tests and a production build on November 10, 2026.

React 19 · TypeScript · Vite · React Router · localStorage · GitHub Copilot
